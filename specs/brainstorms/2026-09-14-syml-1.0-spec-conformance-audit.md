# Audit: SYML spec (text labelled v1.1) vs `syml` 0.6.2 implementation

Empirical run on 2026-09-14 at commit `2bfd6e6`. Every ```syml block in
`SYML-SPECIFICATION.md` that states an Output (JSON) or ERROR was extracted
and run through `syml.loads`, bare and with a trailing `\n`. The extraction
rule (every fenced syml block stating Output or ERROR) is the seed for the R1
acceptance suite in the companion requirements doc. The throwaway harness
scripts are deliberately not committed: `tools/` is under the coverage and
mypy gates.

## (a) Spec-example conformance: 27 / 53 pass, 26 fail

53 blocks state an Output (36 value, 17 ERROR). No case diverged between bare
and trailing-newline runs, so §4.8's trailing-newline equivalence holds today.

| Root cause | Failing sections |
|---|---|
| No quoted-string support at all | §4.7 (×3 value), §4.7/§8.5 unterminated (×2), §4.7/§8.5 trailing-content (×2) |
| `>=` sibling acceptance / no closed-node rule (B4) | §4.2 invalid, §8.1, §5.3 `note: hello`, §7.6 `Warning:`, §6.4 `a:\n b: 1\n plain` |
| No continuation baseline / termination check (B5, D11) | §5.3 (×4: preserve-indent, `key:\n a\n b`, root scalar `hello\n world\nagain`, `key: a\n    b\n  c`), §5.3 `key: a\nb` |
| Empty value → `None` not `""` | §4.3 `#tag: value`, §7.3 `empty:`, §12.3 (`empty:` inside) |
| Missing `&eol` guards on structure rules (A10/D16) | §4.6 bare `-`, §7.5 `key:value` (raises `IncompleteParseError`) |
| Tab handling | §7.5 `key:\tv`, §7.5 `key: \tv`, §8.4 `\tkey: value` |
| Missing error classes | §8.3 duplicate key |

## (b) Verified gap list

Sizes: S ≤ ~½ day, M ≈ 1–3 days, L ≈ a week+.

1. **Quoted strings absent** — §4.1, §4.7, §7.5, §8.5. `padded: "  hello  "` → got `{'padded': '"  hello  "'}`, want `{'padded': '  hello  '}`. Also `key:"value"` (grammar's `ws?` for quoted) → `IncompleteParseError`; `k: "\ud800"`, `k: "\U00110000"`, `k: "a\xb"` all pass through verbatim instead of raising. **L — grammar + error taxonomy.**
2. **Quoting must be inline-only, and inline non-quote fallthrough must raise** — §4.1 quote-guard, D2/M19. `key: "a"\n  b` → got `{'key': '"a"\nb'}`, want `OutOfContextNodeError` (quoted value is complete). `key: He said\n  'yes'` must join as text `"He said\n'yes'"` — that one already matches. **M — grammar + tree-builder.**
3. **Sibling acceptance is `>=`, not `==`; closed nodes still absorb** — §4.2, §8.1, §9.3, B4. `parent:\n  child1: value\n child2: value` → got `{'parent': {'child1': 'value'}, 'child2': 'value'}`, want `OutOfContextNodeError`. Same for the 3-space variant, `note: hello\n  more: text`, `a: Note\n  Warning: do not touch`. **M — tree-builder (`ParentNode.can_add_node`).**
4. **No continuation baseline; indentation flattened; below-baseline never terminates** — §5.3, D11, B5. `key:\n  first\n    indented\n  back` → got `{'key': 'first\nindented\nback'}`, want `'first\n  indented\nback'`. `key: a\nb` → got `{'key': 'a\nb'}`, want `OutOfContextNodeError`. `TextLeafNode.can_add_node` ignores level entirely. **M — tree-builder.**
5. **Plain text at a container's own level joins instead of raising** — §6.4, §7.6, M24. `a:\n  b: 1\n  plain` → got `{'a': {'b': '1\nplain'}}`, want `OutOfContextNodeError`. **S (falls out of #4) — tree-builder.**
6. **Empty values yield `None`, empty/comment-only documents yield `None`** — §7.3, §7.4, §11.1. `empty:\nnext: value` → got `{'empty': None, ...}`, want `{'empty': '', ...}`. `''` → `None`, `'# just a comment'` → `None`, want `''`. `key: ` (trailing space) → `IncompleteParseError`, want `{'key': ''}` (D6). **S — grammar (`text = ~"[^\n]*"`) + the `None` fallbacks in `ContainerNode`/`Root`.**
7. **Bare `-` list marker unsupported; `key:value` errors instead of falling through** — §4.6, §7.5, §7.6, A10/D16. `-\n  block item` → got `'-\nblock item'`, want `['block item']`. `key:value` → `IncompleteParseError`, want scalar `'key:value'`. `- ` → got `'- '`, want an empty list item. **M — grammar (`&eol` guards, `document = (line "\n")* line?`).**
8. **No §9.0 pre-processing** — §4.8, §9.0, §13.3. BOM: `\ufeffkey: value` → `{'\ufeffkey': 'value'}`; BOM-only doc → `'\ufeff'`, want `''`. CRLF: `a: b\r\nc: d` → `{'a': 'b\r', ...}`. Bare CR: `a: b\rc: d` → one scalar. Tab scan: `\tkey: value` → `{'key': 'value'}` (tabs expanded to 4 spaces in `visit_indent`), want `TabIndentationError`; `key: a\n\tb` joins, want error. **S–M — pre-processing.**
9. **Tab is accepted as separator whitespace (D5 violated)** — §7.5, §4.2 rule 3. `key:\tv` → `{'key': 'v'}`, want scalar `'key:\tv'`; `key: \tv` → `{'key': 'v'}`, want `{'key': '\tv'}` (leading tab preserved). Grammar says `ws = ~" +"`; impl has `ws = ~"[ \t]+"`. **S — grammar.**
10. **No duplicate-key detection** — §8.3, §10.3. `key: value1\nkey: value2` → `{'key': 'value2'}`, want `DuplicateKeyError`. Nested too: `p:\n  a: 1\n  a: 2` → `{'p': {'a': '2'}}`. Must be at incorporation time, not in `as_data()`. **S — tree-builder + error taxonomy.**
11. **Error taxonomy is 2 of 7 classes** — §11.3. Present: `ParseError`, `OutOfContextNodeError`. Missing: `DuplicateKeyError`, `TabIndentationError`, `MalformedQuotedStringError`, `DocumentLimitError`, `UnrepresentableValueError`. Also §11.3 requires every `ParseError` to carry `.message`, `.position`, `.line_text` as named attributes — today they are positional `ValueError` args. **S — error taxonomy.**
12. **Parsimonious exceptions leak** — §11.3, B2. `syml.loads('key:value')` raises `parsimonious.exceptions.IncompleteParseError`, which is not a `syml.ParseError`; callers cannot catch safely. **S — error taxonomy (wrap at the `parse()` boundary).**
13. **`indent = ~"\s*"` swallows whitespace-only lines** — §4.4, §9.0 step 3, B1. `'a:\n        \n  b: c\n  d: e'` → got `{'a': {'b': 'c'}, 'd': 'e'}`, want `{'a': {'b': 'c', 'd': 'e'}}`. **S — grammar.**
14. **Inline key after `- ` does not set the sibling column** — §6.2, M23. `-   name: Alice\n  role: admin` → got `[{'name': 'Alice', 'role': 'admin'}]`, want `OutOfContextNodeError`; `- name: Alice\nrole: admin` (zero indent) also parses, want error. `visit_line` calls `set_level(indent.level)` on the whole subtree, so an inline structure inherits the *line's* indent, not the key's column. Distinct from #3. **M — tree-builder.**
15. **No implementation limits; deep nesting is a crash** — §13.4. Block-nesting at 400 parses; **500, 600, 1000 all raise `builtins.RecursionError`** (`incorporate_node`/`get_tip`/`as_data` all recurse). Want `DocumentLimitError`. No line-length or document-size check either. **M — new (limits + error taxonomy).** *Deferred from 1.0 by decision; see requirements doc.*
16. **Source positions miscount lines around Unicode line separators** — §10.2, §13.3, M12. `parsers.parse('a: b\u2028c\nx: y').as_source()` reports key `x` at `Pos(index=7, line=3, column=0)`; it is on line 2. Cause: `utils.split_lines` uses `str.splitlines()`. **S — pre-processing / `utils.py`.**
17. **No `dumps` / `dump`** — §11.2, §11.2.1–.4. `hasattr(syml,'dumps')` → `False`. Requires the quoting table, `UnrepresentableValueError`, one-space-after-`-`, no block continuation for embedded newlines, and the §11.2.4 root-scalar restrictions. **L — new API.**
18. **`load()` decode policy** — §11.1, M13. Signature takes `TextIOBase` and calls `.read()`; strict-UTF-8 decoding is never performed by syml. **S — API.**
19. **Hygiene: `tests/test_nodes.py` is tracked and 0 bytes**, with an untracked `test_nodes.py.orig` (11,413 bytes, hidden by the global `*.orig` gitignore). `nodes.py` is at 100% coverage only because 17 of its branches carry `# pragma: nocover` — including the entire `as_source()` surface, which is reachable and demonstrably works. **S — hygiene.**
20. **Hygiene: importing `syml` emits two `SyntaxWarning: invalid escape sequence '\s'`** (Parsimonious compiling the `~"\s*"` / `~"[^\s:]+"` terminals). Goes away with the §4.1 grammar rewrite. **S — hygiene.**
21. **Hygiene: `pyproject.toml` still declares `version = "0.6.2"`.** `tox.ini` is already gone (review m6 resolved). **S — hygiene.**

Two spec examples already conform where you might not expect: `#tag: value` is a comment (B9's key-unreachability matches), and `- name: Alice\n  role: admin`, `- - x`, `key: - not a list` (§7.2 asymmetry) all already produce the spec's output.

## (c) todo.txt items the reviewed spec superseded or reversed

- **A1's OPEN QUESTION** ("trailing content after a closing quote — scalar fallback vs error, decide before implementing") is **decided**: D2/M2/§4.7 make it `MalformedQuotedStringError`. Same for unterminated quotes and invalid escapes. Do not re-litigate.
- **A1 scope narrowed**: quoting is now recognized **only** at inline positions. Root scalars, block-value lines, and continuation lines never quote-decode. `key:"value"` (no space) stays valid — todo S1 confirmed; the grammar's `key_value = (key_colon ws? quoted_value ~" *") / ...` keeps the optional whitespace for quoted values only.
- **A3 reversed on class**: the spec raises `TabIndentationError`, not a generic `ParseError`, and detection moves to §9.0 pre-processing, before the grammar — not `indent = ~" *"` doing the work.
- **A4 resolved on class**: no `InconsistentIndentationError`; D7 folds §8.1 into `OutOfContextNodeError`. Also A4 understates the fix — the spec needs `>=`→`==` plus a closed-node rule, not just an indentation check.
- **A9 superseded by D11**: todo says "baseline set by the first continuation line". The spec sets a **block** value's baseline from its first *block* line, and adds the below-baseline **termination + re-offer** rule (B5) that todo never mentions. `key:\n  a\n b` is now an error, and `key: a\n    b\n  c` is now an error — neither appears in todo.
- **A10 superseded by D16**: the top rule became `document = (line "\n")* line?` with `eol` lookahead-only; todo's `lines = line*` framing is gone. `list_item = ("-" ws value) / ("-" &eol)` survives.
- **A2 extended**: D6 adds that `key: ` (trailing space) and `- ` normalize to *no value*, not to `""`. The outcome coincides (`""` by §7.3), but the reasoning changed and `key: ""` is now the only explicit empty string.
- **E ("verified as already conformant") is stale in three places**: §6.4 mixed content (`a:\n  b: 1\n  plain` now errors), §5.1/5.2 multiline joining (D11/D13 changed which lines join), and §7.5 whitespace (`key: \tv` must keep the tab).
- **B3 still live** — the dead `return self + other.text` in `basetypes.py` is still there. **m6 (`tox.ini`) already done.**
- **Section D ordering is stale**: A5 (key-pattern narrowing to exclude C0/C1) is still valid and still unimplemented (`a\x01b: v` → `{'a\x01b': 'v'}`), but it now also needs D15's Unicode `White_Space` set, which todo doesn't mention.

## (d) Ambiguities surfaced (resolution recorded in the requirements doc)

1. `dumps`/`dump` in scope for 1.0? → **Yes.**
2. Source tracking (§10) a supported surface? → **Yes, tested; positions in original text.**
3. `Pos` coordinates in original or normalized text? → **Original.**
4. §13.4 limits: config API, depth-level definition, `DocumentLimitError` vs `ParseError` distinguishability? → **Deferred from 1.0 entirely.**
5. `load()` binary vs text stream? → **Both.**
6. D15 `White_Space` vs Python `re` `\s` (also matches U+001C–U+001F) vs §4.1's `\x00-\x1f` key class: which rule rejects `key\x1cname: v`, and how? → **Deferred to planning.**
7. Trailing-whitespace fixtures: the pre-commit `trailing-whitespace` hook strips them, so `key: `, `- `, and §7.5 preservation cases need programmatic construction. → **Deferred to planning.**
8. Breaking-change posture vs 0.6.2 (`key: 'Tis` becomes an error; duplicate keys raise). → **Clean break, documented.**
